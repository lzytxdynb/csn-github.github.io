# 更新记录

## 0.5 / 2026-10-19-stop-1

**可用演示**：商家后台新增“门店停课与演示课时返还”。管理员只能对未来且不存在已核销预约的课程，选择教练请假、场地调整、临时闭店或其他门店原因后确认停课。待上课预约改为“已取消/门店停课”，每条恰好返还1节演示课时；先前取消的不返还，重复停课不重复退款。停课原因、时间、返还数量记入本浏览器审计与门店公告，不会发给真实会员。

**三端联动**：会员课程列表不再开放已停课课程预约，会员历史预约解释模拟返还；教练课表标示停课、不得核销；商家“在排课程”排除停课课程。日历取消状态同步，取消课程不进入前台提醒和 ICS 导出；停课时段资源可用于新排课，原预约不自动迁移。

**测试**：57项Node逻辑测试（0.5新增12项，之前45项）全部通过；53项隔离浏览器UI检查（本轮停课16项、原gym 16项、原calendar 21项）通过，没有发现浏览器JavaScript异常；覆盖重复返还、已核销保护、原因校验、角色限制、课时守恒、停课后预约封锁、资源重新排课、日历提醒、390px布局。版本提交可按 Git commit 回滚。

**限制**：本次离线浏览器用原始HTML/CSS/JS及模拟localStorage，不是公网或微信真机验收。GitHub Pages构建和部署成功不代表实际网页加载无异常；当前执行环境无法直接浏览 Pages 公网域名。浏览器数据不跨设备，商家/教练/会员只是演示角色切换，不能作为正式生产权限。没有实现真实现金退款、微信/短信订阅消息、后端定时推送；原生Windows微信小程序源码不可访问，本轮未同步。下一轮优先多位虚构会员与满员候补。

## 0.4 / 2026-10-18-ops-1

新增「课卡与预约规则」面板：会员查看私教/团课卡有效期与状态，提交1至30天冻结申请、撤回；商家批准/拒绝、登记延长有效期、调整预约与退改截止。冻结批准后立即生效、顺延有效期，不增减余额。相交待上课预约会阻止批准，避免静默取消用户课程。冻结期结束后按时间计算恢复，不依赖定时后台。

预约确认增加开课时间、课卡有效性、上课日期是否在有效期内、会员课程冲突校验；新增排课检查教练与场地重叠，支持跨午夜。取消/改约默认至少提前120分钟，预约默认提前30分钟，商家可调整。教练核销限制为本人课程、开课前15分钟至课后48小时，不可重复核销。

保留原有三端、日历、提醒、演示资料；首次迁移尽可能保存 jingluo-demo-v5-before-ops1 备份。新课卡操作先校验和写入存储再更新界面；浏览器拒绝存储时显示错误。旧页面仍是演示实现，不具有数据库并发安全。恢复使用用户第二张鲸鱼Logo，新增WebP资源。

验证：45项逻辑测试（27新增+18日历），37项隔离浏览器检查（16新增+21回归）；没有捕获浏览器JavaScript异常。检查范围含角色联动、冻结冲突、存储拒绝、课时不变、390px布局。原始报告与浏览器脚本随本次源码包交付，gym.test.cjs在仓库可直接使用Node运行。未完成公网点击、微信真机、系统通知和真实后端验收；未同步离线Windows电脑。

继续事项见 ROADMAP.md。此更新不包含候补、真实支付、门禁或微信消息接入，不应当作生产经营系统使用。
