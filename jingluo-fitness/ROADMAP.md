# 鲸落健身持续迭代路线图

更新：2026-10-20。目标是覆盖健身房日常经营，不用未接入的按钮冒充可用功能。当前本目录仍是虚构资料、单浏览器存储的网页演示；原生微信小程序、生产后端是独立交付范围。

## 当前已实现的演示

三角色入口、基础预约/改约/取消、课时登记、教练核销与课后文字记录、商家排课公告；三端日/周/月课表、网页前台提醒、ICS快照导出。0.4新增预约/退改截止规则、会员/教练/场地时间冲突检查、核销窗口、课卡有效期与冻结审批。0.5新增商家停课、已预约记录标记为停课、模拟课时逐笔返还、停课原因审计及三端日历联动。0.6新增已有演示操作流水只读筛选与 CSV 本地导出。品牌图标使用用户第二张鲸鱼Logo的WebP优化版。

0.5完整回归：57项Node逻辑测试通过（含新增12项商家停课测试）；53项隔离浏览器交互检查通过（新增停课16项、0.4回归16项、日历回归21项）。上一版本0.4：27项新增业务逻辑测试、18项日历逻辑测试，16项新增隔离浏览器检查与21项日历回归检查通过。改约提醒的回归样例显式设定5分钟退改截止，适配新增规则；默认仍为120分钟。

浏览器网络导航在当前执行环境被管理策略阻止。测试使用原始JS/CSS、内存localStorage适配器和Logo内联，不验证公网资源加载、真实持久化、生产CSP、Service Worker、系统通知或微信真机。GitHub Pages构建成功也不能代替这些验收。

本轮未更新用户离线Windows电脑中的原生小程序和服务端；已有源码压缩包不证明远端电脑文件已经同步。不能声称本轮完成了正式微信小程序。

## 迭代规则

只更新 jingluo-fitness/，不动原站。先读最新main，保留可回滚提交，不force覆盖并发修改。只有通过测试的演示模块才提交；正式发布需另行验证身份/消息/资金/数据。前台提醒保留关闭页面后不保证触发的说明。卡片冻结本版从批准时起立即生效，1至30天，期限自动顺延；有相交待上课预约则拒绝批准，不自动退课、不支持提前解冻。现有预约执行退改时使用当前门店规则；生产版需保存预约时的条款快照。

任务环境若缺少GitHub写入、代码执行或平台账号，只记录真实阻塞，不声称实现，不反复安装无关MCP。完成本清单并经实际验收后总结并关闭任务。

## 0.5 停课规则与当前限制

商家可对未开始且没有已核销记录的演示课程选择预设原因并确认停课；所有待上课预约被标为门店停课并各返还1节演示课时，已取消预约不会再次返还，重复停课会被拒绝。停课记录保留时间、原因、涉及人数与本浏览器审计日志；会员历史记录显示“门店停课/课时已返还”，教练与商家日历把课程标记为取消，前台提醒和 ICS 导出排除取消课程。已停课课程释放演示排课资源。无法一键恢复；如需重排必须重新创建课程，原预约不自动转移。没有真实退费、短信、微信通知或跨设备同步。以上仍然属于单浏览器模拟，角色切换不是服务端权限控制。

本轮没有公网三个角色的真实点击验收：当前运行环境无法连接 GitHub Pages 域名，GitHub Actions 构建成功不是公网验收。已执行离线原始脚本的逻辑和隔离浏览器测试，未声称网站公网或微信小程序已验收。若公开地址有问题，以实际浏览器显示为准。

## 0.6 操作日志查询说明与待办

本轮只新增商家演示后台的只读日志面板，来源是本浏览器既有的 `logs`、`gym.audit` 以及可选的 `auditTrail`。可以按操作类型筛选和下载 CSV，不采集新的身份凭据。原始文字日志的角色只能推断或显示未知，不能当作真实操作人取证；记录可以被访问者本地修改或清空。日志列表最多200条，默认展开显示最近25条；不修改已有预约/课卡业务逻辑。

验证为 JavaScript V8 断言测试，附带 `audit-legacy.test.cjs` 供以后 Node 复跑；未做真实 GitHub Pages 三端点击、真实 CSS/JS 公网加载或 CSV 真机下载验收，构建成功不等于公网验收。Windows 设备离线，原生小程序未同步。下一轮继续 P0 多位虚构会员与候补补位，尤其注意模拟账户身份和课时余额的隔离及幂等返还。
